CPKS induction on the GPU

SAPT(DFT) CPKS induction now builds the XC response kernel (compute_Vx) on the cuEST grid for native LDA/GGA RKS singlet, RKS triplet and UKS, with the existing CPKS J/K factors reused. The kernel derivatives come from CUDA LibXC when the build has it, otherwise from host LibXC (CUEST_XC_RESPONSE_HOST_LIBXC forces the host route). mGGA, VV10, direct J/K and analytic Hessians are out of scope.

48/48 grid-switch tests pass on the H200, including a live V that goes final → initial → final twice with its response caches populated. Switching 25×110 → 75×302 leaves CPKS cost unchanged (peptide 1.97 vs 2.00 s; nanotube 8.07 vs 8.06 s); polarizabilities agree to ≤ 3e-8 relative. On the CPU, the switched peptide SCF was slower (17.2 vs 14.7 s), in line with the tiny-grid pilot.

Correctness, memory and limits

H200, CUDA LibXC build (cuEST 0.2.50): 148 tests pass, 6 fail — 4 pre-existing cuEST wK long-range-corrected fixed-orbital cases (cam-b3lyp, lrc-wpbe) and 2 svwn empty-beta cases from an oracle since fixed; SDK normalization/signed-density contract 18/18 clean; CUDA vs host LibXC derivatives ≤ 1.7e-17.

GPU memory: each live V holds a cached cuEST response workspace sized by CUEST_XC_RESPONSE_BUDGET_MB (default 2000 MB, ≈ 2 GB per V, ×2 for SAPT monomers), outside Psi4's GPU budget, freed by V.finalize(). Results are budget-independent (≤ 1e-16); 500 MB costs ≤ 1% time through coronene (660 nbf), 16 MB up to 2.2×.
